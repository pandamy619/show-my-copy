# Security policy

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub: **Security → Report a vulnerability** in this repository. Do not open a public issue, and do not include real clipboard contents or passwords in the report.

## Supported versions

There are no releases yet. Security fixes go to the `main` branch; once releases exist, only the latest one will get them.

## Security model

### Today (0.1)

- **No network.** The app is sandboxed without network entitlements, so macOS blocks any connection it tries to make. CI builds the Release configuration with ad-hoc signing and checks its signed entitlements (`make security`).
- **Stored on this Mac only.** The history is saved in the app's sandbox container (`~/Library/Containers/…/Data/Library/Application Support/ShowMyCopy/History.store`, a SwiftData/SQLite store) so it survives quitting the app. It is never synced (no CloudKit) or sent anywhere, and the folder is excluded from Time Machine and other backups. Clear History in Settings deletes it from disk as well; removed and expired entries are deleted from disk right away.
- **Images are files in the same folder.** A copied image is saved unchanged, with a PNG thumbnail of at most 256 pixels, as separate files in `Application Support/ShowMyCopy/Blobs/` in the container, also excluded from backups; the database holds only their IDs, size and type. They are not encrypted (FileVault protects them at rest). Removing an entry, the history limits and Clear History delete its files; files no entry uses any more (for example after a crash) are deleted at the next launch. Images are read with ImageIO only to measure them, draw the thumbnail and show it; the full image is read only when you open its preview in the history window, decoded at most 2048 pixels on its longer side, and dropped when the preview closes. The preview of styled text reads the copied data as RTF only (never as HTML) and drops attachments and links, so it cannot load anything or open a link.
- **Files are references only.** For copied files the history keeps the path, the name and, when the sandbox allows reading it, the size: never the contents and no access rights (no security-scoped bookmarks). The app cannot follow a moved file, and in the sandbox it often cannot tell a deleted file from one it is not allowed to look at, so it can only say a file *may* be unavailable. Paths and file names are stored in plain text in the database.
- **Copied photos and videos are read once for a thumbnail.** When the first files of a copy (up to 4) are images or movies, the app reads each of them once, right when it is copied, to make a PNG thumbnail of at most 256 pixels with QuickLook (`QLThumbnailGenerator`, which draws a frame of a video, in a system process). The sandbox allows this only because reading the file URLs from the pasteboard gives the app access to those files until it quits; it asks for no file entitlements. Only the thumbnail is kept, in the `Blobs` folder next to image thumbnails, not encrypted, and deleted with its entry; nothing else of the file is copied or kept. So that this never downloads anything, the app skips URLs that are not file URLs, files on network volumes, and iCloud or other cloud files whose data is not on this Mac (not downloaded, or "dataless" placeholders). Files that cannot be read, or take longer than 3 seconds (5 seconds for the whole copy), keep their icons. A thumbnail shows what the photo or video looked like when it was copied, even after the file is changed or deleted.
- **Passwords are not kept by default.** Items marked as concealed (see [nspasteboard.org](http://nspasteboard.org)) or with the older markers some password managers use, and anything copied while a known password manager is the frontmost app (1Password, Bitwarden, Passwords, Keychain Access, KeePassXC, Strongbox, LastPass, Proton Pass, Enpass, Keeper), are not recorded, and their text is not read. Items marked as transient or auto-generated are never stored.
- **Cleared passwords leave the history.** Password managers empty the clipboard a while after copying a password. When the clipboard is emptied within 3 minutes of a copy that is still on it, that entry is removed, or hidden with an expiry if you save passwords.
- **Saving passwords is opt-in.** With Settings → Passwords → Save passwords on, passwords are kept masked in the history (the mask does not show their length), revealed one row at a time with the eye button and hidden again when the window closes, left out of text search, never read out by VoiceOver, and removed after 1 minute, 10 minutes (default) or 1 hour. Turning the setting off removes them at once. A password copied back from the history is marked as concealed and kept off Universal Clipboard, so other clipboard managers and your other devices do not get it.
- **Saved passwords are encrypted on disk.** With Save passwords on, each password is encrypted with AES-256-GCM before it is written, padded so its size does not tell the password's length. No hash or preview of a password is stored: a plain hash of a short password could be checked against a list of common passwords. The key is created on this Mac, kept in your Keychain and never synced to iCloud. The app asks the Keychain for it only when a password is saved or a saved password is loaded, so with Save passwords off it never touches the Keychain. Saved passwords that have expired, and all saved passwords once Save passwords is off, are deleted at launch without asking for the key. If the key cannot be read, for example because you deny Show My Copy access to it, passwords are kept in memory only until you quit, Settings → Storage says so, and passwords saved before can no longer be opened and are removed. Everything else is still saved.
- **Passwords are only kept as text.** A secret (marked, or copied from a password manager) is read as plain text only, so a password is never stored as styled text, an image file or a file reference; an image or files marked as concealed are not recorded at all, and an image or file entry that later turns out to be a password (the clipboard is cleared soon after) is removed instead of hidden.
- **Minimal permissions.** The app asks for no permissions: no Accessibility, no Input Monitoring.
- **No secrets in logs.** Clipboard contents are never logged.

### Known limitations

- **Some unmarked passwords are kept.** A password copied without a marker from an app that is not a known password manager — for example from a browser extension or a text file — is kept like any other text, unless a password manager empties the clipboard within 3 minutes. The same rule can remove an ordinary entry when an app empties the clipboard soon after you copy it.
- **The first copy after launch, sleep or unlock** has no known source app, so only markers tell whether it is a password.
- **Saved passwords are plain text in memory** while they are kept; the mask only hides them on screen.
- **Where the encryption key is kept.** The app has no keychain entitlement, so macOS does not let it use the keychain that keeps an item on one Mac only and readable only while the Mac is unlocked. The key is kept in your login keychain instead: Time Machine backs it up, and Migration Assistant can move it to a new Mac together with the history. When the app's code signature changes, for example in a copy you built yourself, macOS asks whether Show My Copy may use the key the next time a password is saved or loaded.
- **Deleted entries may stay on the disk for a while.** The history is an SQLite database. When an entry is deleted, cleared or turned into a password, SQLite marks its old data as free space but does not overwrite it, so it can remain in the database file and in free disk blocks until it is overwritten. FileVault protects it while the Mac is off or locked. The same goes for the files of deleted images and thumbnails. Passwords are written to disk only encrypted, so this applies to their encrypted form only, unless an entry was saved as normal text before it was recognized as a password.
- **Some details of saved passwords are not encrypted:** when they were copied, from which app, and when they expire.
- **A damaged history file is kept aside.** If the history file cannot be opened, it is renamed to `History.store.damaged` (replacing an older one) in the same folder, and a new, empty history starts.
- **Password manager list.** Some bundle identifiers (Proton Pass, Keeper, LastPass, Enpass, Strongbox Pro) are taken from third-party catalogs and still have to be checked on a Mac; Dashlane and NordPass are not listed yet.
- **Screen sharing.** The history window uses the standard macOS opt-out from screen sharing, screenshots and screen recordings. Some newer capture methods (ScreenCaptureKit on recent macOS versions) may still capture it.
